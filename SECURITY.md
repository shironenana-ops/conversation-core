# Security Policy

## Supported version

The experimental `0.1.x` line receives best-effort security fixes.

## Reporting

Do not open a public issue containing credentials, private conversations, or exploitable details. Use GitHub private vulnerability reporting when enabled, or contact the repository owner through a private channel listed on their GitHub profile.

Never commit `.env` files, tokens, private imports, real chat exports, or generated private cores. Inspect staged changes before every push. The offline extractor is the default; no content is sent to an external provider.
